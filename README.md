# ぶいすぽっ！ラジオ | Radio Shelf

ぶいすぽっ！ファンクラブの**公式ラジオ個別ページを整理する個人用・非公式Webアプリ**です。音声や画像の収集・再配信・ダウンロード、会員認証の自動化は行いません。

- 公開URL: https://mikisaa.github.io/vspo-radio-shelf/

## 機能

- 公式URLを登録、検索（番組名・回数・出演者・メモ）、タイトル・出演者・公開日・メモを編集
- 公式ページからコピーした複数のURLを貼り付けて、過去回を一括追加（重複除外）
- お気に入り／視聴済み（手動）／未視聴の絞り込み
- 「公式で聴く」からSafari等の公式個別ページを開く。バックグラウンド再生・ロック画面操作は公式サイトの挙動に依存
- 公式のお知らせ文を貼るとURL、回数、日付を可能な範囲で抽出
- カタログ同期: 起動時／再表示時／30分ごと／手動で `catalog.json` を確認（全118件収録済み）
- 旧バージョンの初期4件データをお使いの端末も、お気に入り・視聴済み・手動編集メモを保持したまま正式表記へ自動マイグレーション
- JSONバックアップ／復元（`radio-shelf-v1` 互換維持）
- iPhone「ホーム画面に追加」対応のPWA（ノッチ／Dynamic Island の safe area 対応済み）
- 他のアプリから `https://mikisaa.github.io/vspo-radio-shelf/?add=<URLエンコードした公式URL>` で追加画面を開ける

## 重要な制約

- **会員領域の自動巡回・解析は行いません。** 新着登録は一般公開されている公式NEWS（`https://fc.vspo.jp/post`）に掲載された公開お知らせのみを確認対象とし、会員ログインの自動化・内部API解析・音声取得・連番からのURL推測は一切行いません。
- 共通マスタは `catalog.json` です（`core.js` の `INITIAL_CATALOG` はオフライン用の初期118件スナップショットとして保持）。公開NEWSに掲載された新着回（`radio119` 以降）は `scripts/sync-public-news.mjs` / GitHub Actions により `catalog.json` へ自動追記されますが、公開NEWSには固有番組名や出演者名が記載されないため、未確認項目は捏造せず空欄または `第○回ラジオ` 表記で登録されます（公開NEWSに掲載されない更新は自動検出されません）。
- 個人データ（お気に入り・視聴済み・メモ・非表示状態・手動追加分）は各端末の `localStorage` に保存されます。端末間同期はありません。ブラウザデータ削除で消えることがあるため、JSONバックアップを推奨します。
- アプリのシェル（キャッシュ名 `radio-shelf-v7`）だけオフライン表示可能です。公式ラジオの再生にはインターネット接続・ファンクラブ会員ログインが必須です。
- 再生画面は**外部の公式サイト**で開きます。自作アプリ内にプレーヤーを埋め込むものではありません。
- このアプリはぶいすぽっ！および運営会社の公式・公認アプリではありません。

### 公式の視聴制限と出典メモ

- `gallery/radio番号` は3番組を通した通算番号であり、各番組の `第○回` とは一致しません。新着追加時も連番からURLや回数を推測して生成しません。

## iPhoneのホーム画面への追加・更新方法

### 初回追加手順
1. iPhone の **Safari** で `https://mikisaa.github.io/vspo-radio-shelf/` を開きます。
2. 画面下の **共有ボタン** → **「ホーム画面に追加」** → 右上の **「追加」** をタップします。
3. ホーム画面の「ぶいすぽっ！ラジオ」アイコンから起動し、各回の「公式で聴く」をタップすると公式個別ページが開きます（事前に Safari で公式ファンクラブへログインしておくとスムーズです）。

### アプリ・データの更新手順
- **新着カタログの同期**: アプリ起動時・再表示時・30分ごとに自動で確認します。手動で反映したい場合は画面内の **「更新確認」**（または右上の設定ボタン → **「今すぐ確認」**）をタップします。お気に入り・視聴済み・メモはそのまま維持されます。
- **画面デザイン・キャッシュの更新（現在 `radio-shelf-v7`）**:
  - 通常はアプリを開き直す（または一度タスクキルして再起動する）と新しい Service Worker キャッシュ（`radio-shelf-v7`）へ更新されます。
  - iOS の仕様により、ステータスバー設定やアイコン変更が既存のホーム画面アイコンに反映されない場合は、以下の手順で安全に再追加できます。
    1. 右上の設定ボタン → **「JSON書き出し」** でバックアップファイルを保存する
    2. ホーム画面のアイコンを削除し、Safari で公開URLを開き直して再度 **「ホーム画面に追加」** する
    3. 必要に応じて設定 → **「JSON読み込み」** からバックアップを復元する（※ Safari 全体の履歴とWebサイトデータを消去しない限り、再追加後も `localStorage` データは引き継がれる場合がありますが、念のため事前バックアップを推奨します）

## ローカルで動作確認する

1. ファイルを任意のフォルダに展開する。
2. フォルダ内で `python -m http.server 8000` を実行する（Pythonがある場合）。
3. ブラウザで `http://localhost:8000` にアクセスする。
4. `npm test`（`node --test tests/*.test.js`）でロジック・マイグレーションテストを実行可能。

## GitHub Pagesで公開する

1. リポジトリ `mikisaa/vspo-radio-shelf` は作成済み・Publicです。アプリのファイルは `main` の直下に配置済みです。
2. アプリの更新時は `main` に変更をコミット・pushします。
3. GitHub の **Settings → Pages → Build and deployment → Source → GitHub Actions**（推奨：GitHub Actions の `GITHUB_TOKEN` による自動カタログ更新コミットでも確実に Pages が再デプロイされます。従来の Deploy from a branch を使う場合は `PAGES_DEPLOY_TOKEN` シークレットを設定）で公開されます。

> GitHub Pages上のHTML/CSS/JSと `catalog.json` は公開されます。パスワード・Cookie・会員向け音声・個人メモは絶対にコミットしないでください。メモ・お気に入り状態は公開されず端末内にあります。

## カタログ更新の仕組み

今後 `radio119` 以降の新着回が公開された際は、[`docs/PAST_RADIO_IMPORT.md`](docs/PAST_RADIO_IMPORT.md) の手順に従い、確認済み候補JSONを `node scripts/import-archive.mjs archive-candidates.json` で dry-run 検証したうえで、`--write` を付けて `catalog.json` に安全に追記できます（必要に応じ `core.js` の `INITIAL_CATALOG` も同期）。

```json
{
  "version": "2026-11-17-archive-import",
  "items": [
    {
      "url": "https://fc.vspo.jp/gallery/radio118",
      "title": "【第75回】ぶいすぽっ！の雑談部今日も解散できません！",
      "date": "2026-11-12",
      "hosts": "兎咲ミミ/蝶屋はなび",
      "notes": ""
    }
  ]
}
```

バージョンやファイル名に機密データは含めないでください。

## 新着エピソード自動登録（v1.5）

公式利用規約を尊重し、未ログインで一般公開されている公式NEWS一覧（`https://fc.vspo.jp/post`）から「ラジオコンテンツ更新のお知らせ」等の公開記事のみを低頻度で定期確認し、明記された事実情報（個別URL・回数・公開日）だけを `catalog.json` へ安全に自動追記します（`.github/workflows/sync-new-radio.yml` / `scripts/sync-public-news.mjs`）。記事本文や画像・音声の転載・収集、会員領域の解析は一切行いません。

- **自動化できる範囲**: 公開NEWSに掲載された個別ラジオURL、公開日、回数表記（例：`第76回ラジオ`）の検出・重複除外・検証・`catalog.json` 追記・テスト実行・GitHub Pages デプロイおよび反映確認。
- **自動化できない範囲**: 公開NEWSに記載されない固有番組名・出演者名（捏造せず空欄等で登録）、公開NEWS自体に掲載されなかった回、会員限定領域の情報。
- **役割分担と競合防止**: 新着登録の主担当は GitHub Actions とします（外部の監視タスクは確認・異常通知専用とし二重書き込みを行わない前提）。手動更新との競合に備え、ファイルロック、直前の最新 `origin/main` 取得と `episodeKey` 重複スキップ（新着なし・既登録時は無変更）、non-fast-forward 時の自動再取得・再判定、およびリポジトリ変数 `DISABLE_AUTO_SYNC=true` による定期実行の一時停止に対応しています。
